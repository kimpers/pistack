# Native delegation and models

The parent owns routing, orchestration and acceptance. Children complete only assigned work. Read the installed pi-subagents skill and public guide for the branch used. Inspect `subagent({ action: "list", capabilities: true })` and `subagent({ action: "models" })` before launch. Listing does not prove authentication or launch compatibility. Missing tools/agents/providers and launch failures block the lane; capture its run id, cwd, branch/ref, partial diff and failure before a clear same-protocol retry. Never substitute a shell-agent, external CLI or foreground executor.

## Roles

Use `pistack.analyst` for local source exploration, explanations, design sketches in returned artifacts, critics and read-only review. It has `read, grep, find, ls`, no mutation tools and no ambient extensions. For git/gh, executable verification or MCP evidence it cannot collect, the parent supplies bounded, cited evidence using its own authorized tools. If independent execution is required, use an already configured, discovered validator/investigator profile with exactly those tools and provider loaded. Otherwise report the capability gap and ask; do not pretend source review is live verification. MCP access requires an authorized read-only tool selection and its loaded provider, not a blanket grant of write access. There is no bundled connector/auth configuration.

Use `pistack.poteto-agent` for implementation in one owned cwd and `pistack.comment-sicko` for comment-only edits. A branch alone is not write isolation. Parallel code candidates use native managed `worktree: true`; the source must be clean and `baseRef` must be `HEAD` or a supported named ref, not a raw SHA or revision expression. If dirty foundation work must be preserved, serialize one writer in that cwd or pause for an authorized isolation decision. Never reset/stash another actor's work. Use unique runtime `output` bindings for report-only candidates. Read the returned handoff manifest and patch before applying managed results; managed worktrees may already be cleaned up. Do not assume persistent worker branches.

## Model policy

`/pistack setup` discovers provider/model IDs from the live scoped registry. `/pistack doctor` identifies the effective config path; read that `pistack.json` for direct skills. Trusted project config replaces user config as a whole. With no config, use `defaultModels()` in [models.ts](../lib/models.ts): each role explicitly inherits the immediate parent, with four slots for how critics, arena runners/cross-judge pool, architect runners and interrogate reviewers, and one for other roles. Reflect always has three lenses plus one synthesizer. How exploration has 2–4 source slices; why has one investigator per available category. Swarm N comes from coverage/race scope. None of these counts equals concurrency.

Validate every selected ID against current discovery and apply the configured role model per run. `inherit` resolves to the immediate parent's current provider/model, never a literal registry ID. Do not silently substitute unavailable choices; use setup after approval. Respect user/project agent overrides and scoped-model restrictions. Panel entries are independent contexts, even when IDs repeat. Report actual model IDs and disclose same-model panels; distinct IDs do not imply different families. Prefer a different-family judge when available, otherwise label the independent same-model review and its limitation. A required diverse-model gate remains unmet unless the user accepts that limitation.

## Launch, join, cancel

For one bounded child the documented shape is `subagent({ agent: "pistack.analyst", task: "<self-contained brief>", model: "<resolved provider/model>", context: "fresh", async: true })`. These are placeholders to resolve before calling, not executable examples. Keep briefs self-contained: objective, repo/cwd/ref, read/write fence, named source contracts, constraints, acceptance, verification, output and stop/ask conditions. Pass templates and source paths, not a transcript dump. No child launches siblings; the parent runs each stage.

For sequencing/fanout use `workflowScript` with awaited `runs.run(key, item)` or `runs.all(items)` and an explicit return. `runs.all` returns an ordered array. Bound active batches to configured concurrency while preserving total panel N. Every launched promise must be observed. Validate authored scripts with `action: "validate"` before launch; no nested async helpers or legacy top-level task arrays. Use `output` plus `outputMode: "file-only"` for durable bounded report references. A read-only child returns its artifact for runtime persistence; it does not need write tools. Check `ok`, terminal state, errors and required artifacts before downstream stages; do not judge partial candidates.

Background completion notifications are native. Yield when only children are running; do not busy-poll or create another wake loop. Inspect exact-run `action: "status"` on attention or recovery. `action: "steer"` acknowledges input, not compliance. `action: "interrupt", id` requests a resumable pause; verify terminal/paused state before transferring ownership. `action: "stop", id` ends an owned current-session top-level async run and is not resumable; stopped work restarts fresh. Never stop unrelated runs. Race losers must be joined or explicitly canceled and reconciled after the declared selection rule; coverage requires every required slice, so a dropout cannot silently pass.

`action: "children.list"` reports resumability. `action: "resume", id, message` revives retained session context, not a live child, and preserves its model/tools. Resume only a reported resumable child with consolidated current scope. Prefer fresh reviewers; never blindly chain interrupts or use resume as a liveness probe. Child blocking questions use native `contact_supervisor`; parent replies through `subagent_supervisor`. A tool receipt or child acceptance report is evidence, not parent acceptance or publication authority.
