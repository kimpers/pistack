### Managed worktree cleanup

Read [the Pi integration contract](../../../../pi/references/integration.md) first. Paths in prose are relative to the poteto-mode skill directory unless explicitly linked.


**Audit local managed workers only.** Read [runtime](../../../../pi/references/runtime.md). Unrelated worktrees, simulators, IDE state, caches and remote branches are outside this port's cleanup scope. Deletion needs explicit approval and fresh ownership proof.

1. Inventory `git worktree list --porcelain` and exact native run/handoff records for this task. Record disk usage if useful. Run the read-only `scripts/worktree-audit.sh [--base REF] <repo> <owned-evidence.json>` with the explicit task-local envelope in [runtime](../../../../pi/references/runtime.md). To compare heads against a local integration base, pass `--base refs/heads/integration`. The audit resolves it once and reports the input ref, commit ID, and separate ancestry for each row. Without a base, ancestry is `not-requested`. Missing or noncommit bases block the audit. Unknown ancestry holds the row. Known ancestry is advisory and never grants deletion authority. It does not fetch, guess a default branch, delete, kill or infer ownership from transcripts. Missing evidence holds the path. Its fixtures do not establish platform/live integration qualification.
2. Request native `subagent({ action: "worktree.cleanup", mode: "plan", repo: "<verified repo>" })` only through an available authorized tool, after resolving the repo. It is plan-only, not deletion. Missing/malformed ownership evidence or an unrelated path is unknown and excluded, never guessed from a directory name.
3. Reconcile exact live/paused/terminal runs with worktrees, captured patches, base/head refs, merge evidence and user holds. A clean checkout or old timestamp alone does not prove disposable state. Dirty, untracked and ignored files all require preservation/review; no generic scratch exemption.
4. Show the proposed exact paths and evidence to the owner. Stop if active/unknown, unmerged/uncaptured, changed since audit or not explicitly approved. Do not force-remove, recursively delete leftovers, kill by process name or widen to a cache/simulator sweep. Actual removal is a separate operator-owned action after fresh native settlement and Git/evidence checks; this package intentionally provides no removal API. Even `review-owned` audit output has `deletionAuthorized: false`.
5. After any separately approved operator-owned removal, re-list paths and confirm evidence artifacts survive. Report retained candidates with their concrete reason; never invent reclaimed-space numbers.

**Reply:** audited owned paths, proposal versus actual removal, before/after measurements only if taken, retained paths/reasons and unmet evidence/platform gates when applicable.
